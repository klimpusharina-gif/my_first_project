1. В чем разница между event.preventDefault() и event.stopPropagation()? В каких ситуациях используется каждый метод?
`preventDefault()` отменяет стандартное поведение браузера для этого события (например, переход по ссылке, отправка формы, выделение текста). `stopPropagation()` останавливает всплытие (или погружение) события, не давая ему дойти до родительских элементов. `preventDefault` используется для контроля над действиями браузера, `stopPropagation` — для контроля над распространением события по DOM-дереву.

2. Как работает делегирование событий и какие преимущества оно дает по сравнению с назначением обработчиков на отдельные элементы?
Делегирование — это назначение одного обработчика на родительский элемент, который ловит события от дочерних элементов благодаря всплытию. Преимущества: экономия памяти (один обработчик вместо множества), автоматическая поддержка динамически добавленных элементов, меньше кода при изменении списка элементов.

3. Какие фазы жизненного цикла события существуют в JavaScript (capturing, target, bubbling) и как они влияют на порядок выполнения обработчиков?
Событие проходит три фазы: 1) Capturing (погружение) — от корня документа к целевому элементу; 2) Target (цель) — событие достигло целевого элемента; 3) Bubbling (всплытие) — от целевого элемента обратно к корню. По умолчанию обработчики срабатывают на фазе всплытия. Если указать `addEventListener(..., true)` — на фазе погружения.

4. В чем разница между event.target и event.currentTarget? Когда следует использовать каждый из них?
`event.target` — это элемент, на котором произошло событие (самый глубокий элемент). `event.currentTarget` — это элемент, на котором висит текущий обработчик события (может быть родителем). `target` используется для определения источника события, `currentTarget` — для работы с элементом, к которому привязан обработчик.

5. Как создать и запустить кастомное событие? Какие параметры можно передать в конструктор CustomEvent?
Создание: `new CustomEvent('eventName', { detail: data, bubbles: true, cancelable: true })`. Запуск: `element.dispatchEvent(event)`. В конструктор можно передать: `detail` (любые данные), `bubbles` (всплывать ли), `cancelable` (можно ли отменить через preventDefault), `composed` (выходить ли за пределы Shadow DOM).

6. Что такое debounce и throttle? В каких практических ситуациях их применение наиболее эффективно?
`debounce` — откладывает вызов функции до тех пор, пока не пройдет заданное время с момента последнего вызова. Применяется для поиска при вводе, изменения размера окна. `throttle` — ограничивает частоту вызовов (не чаще, чем раз в заданный интервал). Применяется для обработки скролла, движения мыши, частых кликов.

7. Какие методы существуют для удаления обработчиков событий и почему важно удалять ненужные обработчики?
Метод `removeEventListener(type, listener)` удаляет обработчик, если он был добавлен через `addEventListener`. Важно удалять обработчики, когда элемент удаляется из DOM или когда функционал больше не нужен, чтобы избежать утечек памяти и непредвиденных срабатываний.

8. Как обрабатывать ошибки загрузки ресурсов (изображений, скриптов) и какие события для этого используются?
Для изображений используется событие `error` на элементе `img`. Для скриптов — `onerror` на элементе `script`. Также можно использовать события `load` (успешная загрузка) и `loadstart`/`loadend` (начало/окончание загрузки). Для обработки ошибок сети можно использовать `window.addEventListener('error', ...)`.

9. В чем разница между addEventListener и прямым назначением обработчиков через onclick, onkeydown и т.д.?
`addEventListener` позволяет добавить несколько обработчиков на одно событие, не перезаписывая предыдущие. Прямое назначение (`element.onclick = fn`) перезаписывает предыдущий обработчик. Также `addEventListener` позволяет управлять фазой (capturing/bubbling) и легко удалять обработчики через `removeEventListener`.

10. Как оптимизировать производительность при работе с большим количеством событий? Какие лучшие практики существуют?
Использовать делегирование событий, применять `debounce` и `throttle` для частых событий (scroll, resize, input), удалять неиспользуемые обработчики, использовать `requestAnimationFrame` для визуальных обновлений, минимизировать количество DOM-операций внутри обработчиков, использовать пассивные обработчики (`{ passive: true }`) для событий скролла и касаний.
