1. Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?
`required` (обязательное поле), `minlength`/`maxlength` (мин/макс длина текста), `min`/`max` (для чисел и дат), `type` (например, `email`, `tel`, `url` включают встроенные проверки формата), `pattern` (регулярное выражение для проверки).

2. В чем разница между novalidate атрибутом формы и отключением валидации через JavaScript?
`novalidate` отключает встроенную браузерную проверку формы, но позволяет JavaScript выполнять свою (кастомную) валидацию. Отключение через JS (например, удаление атрибута `required`) — это изменение самой разметки, что делает форму менее семантичной.

3. Как правильно связать <label> с полем ввода и почему это важно для доступности?
С помощью атрибута `for` у `<label>`, значение которого совпадает с `id` у `<input>`. Это важно для скринридеров (они озвучивают название поля) и для удобства (клик по тексту метки активирует поле ввода).

4. Какие типы полей input наиболее подходят для разных видов данных (email, телефон, пароль и т.д.)?
Для email — `type="email"`, для телефона — `type="tel"`, для пароля — `type="password"`, для даты — `type="date"`, для ссылок — `type="url"`, для чисел — `type="number"`.

5. Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?
Атрибут `pattern` принимает регулярное выражение. Браузер проверяет значение поля на соответствие этому выражению. Используется для сложных форматов (например, номер телефона, индекс, пароль по требованиям безопасности).

6. Какие события JavaScript используются для реализации валидации в реальном времени и почему?
Событие `input` (срабатывает при каждом изменении) и `blur` (срабатывает при потере фокуса). `input` позволяет моментально убирать ошибки при исправлении, а `blur` — проверять поле, когда пользователь закончил с ним работу.

7. Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?
Использовать атрибуты `aria-live="polite"` или `aria-describedby` для связи поля ввода с текстом ошибки, а также добавлять `aria-invalid="true"` к невалидному полю.

8. В чем преимущества использования fieldset и legend для группировки полей формы?
`fieldset` семантически группирует связанные элементы (например, блок «Личная информация»). `legend` дает название этой группе. Это помогает скринридерам лучше понимать структуру формы.

9. Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?
Нужно написать JavaScript-функцию, которая сравнивает значения двух полей (пароля и подтверждения). При несовпадении — выводить ошибку и блокировать отправку формы.

10. Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?
Псевдоклассы `:valid` (поле валидно) и `:invalid` (поле невалидно), а также `:focus` (в фокусе). Дополнительно используются классы, добавляемые через JS (например, `.error` для красной рамки и анимации).
