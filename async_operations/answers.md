1. В чем разница между Promise.then().catch() и async/await с try/catch? Когда следует использовать каждый подход?
`async/await` — это синтаксический сахар над промисами, который делает асинхронный код похожим на синхронный, что улучшает читаемость. `try/catch` позволяет ловить ошибки так же, как в обычном синхронном коде. `.then().catch()` — это более старый способ, который может быть удобен при построении длинных цепочек, но вложенные колбэки могут сделать код сложным для чтения ("callback hell"). Рекомендуется использовать `async/await` для большинства задач, особенно при работе с последовательными асинхронными операциями.

2. Как работает Promise.all и что происходит, если один из промисов в массиве завершается ошибкой?
`Promise.all` принимает массив промисов и возвращает новый промис, который резолвится, когда все промисы в массиве успешно завершены (возвращает массив результатов). Если хотя бы один промис завершается с ошибкой (rejected), то весь `Promise.all` немедленно отклоняется с этой ошибкой, игнорируя остальные промисы.

3. В чем разница между Promise.all, Promise.race и Promise.allSettled? Приведите практические примеры использования каждого.
`Promise.all` — ждет выполнения всех промисов или первого отказа. Используется, когда нужны результаты всех операций. `Promise.race` — возвращает результат первого завершившегося промиса (успешного или с ошибкой). Используется для таймаутов или когда важен самый быстрый ответ. `Promise.allSettled` — ждет завершения всех промисов, возвращая массив объектов с их статусами (`fulfilled`/`rejected`) и значениями. Используется, когда нужно обработать все результаты, даже если некоторые операции провалились.

4. Как реализовать повторные попытки (retry logic) для асинхронных операций с экспоненциальной задержкой?
Нужно написать функцию, которая возвращает промис и в случае ошибки (в блоке catch) запускает таймер на определенное время (с каждой попыткой время увеличивается: 1с, 2с, 4с...) и рекурсивно вызывает себя, пока не достигнет лимита попыток или не получит успешный результат.

5. Что такое "состояние гонки" (race condition) в асинхронном коде и как его избежать?
Состояние гонки — это ситуация, когда результат выполнения кода зависит от того, какой асинхронный процесс завершится первым. Это может привести к непредсказуемому поведению. Избежать можно с помощью мьютексов/семафоров, использования `Promise.all` для синхронизации или проверки "актуальности" запроса (например, игнорировать устаревшие ответы от API, если был отправлен новый запрос).

6. Как работает кэширование результатов асинхронных запросов и какие стратегии кэширования существуют?
Кэширование сохраняет результаты запросов, чтобы при повторном обращении не делать новый запрос, а взять данные из памяти (например, из `Map`). Стратегии: время жизни (TTL), кэширование по ключу (URL), инвалидация кэша (сброс при изменении данных).

7. Какие методы оптимизации производительности можно применить при работе с множественными асинхронными операциями?
Использовать параллельное выполнение (`Promise.all`) вместо последовательного, ограничивать количество одновременных запросов (например, через пул), использовать кэширование, применять `debounce` для ограничения частоты запросов, а также использовать `AbortController` для отмены ненужных запросов.

8. Как обрабатывать ошибки в цепочках промисов и предотвращать "проглатывание" ошибок?
Всегда добавлять `.catch()` в конце цепочки промисов или оборачивать `await` в `try/catch`. "Проглатывание" происходит, если ошибка возникла в промисе, но у него нет обработчика `.catch()`, и она теряется. Также можно использовать глобальный обработчик `unhandledrejection` для отладки.

9. В чем преимущества использования async/await по сравнению с традиционными промисами и обратными вызовами?
`async/await` делает код более читаемым и линейным, убирает вложенность ("callback hell"), позволяет использовать стандартные конструкции `try/catch` для обработки ошибок и упрощает отладку (стек вызовов становится понятнее).

10. Как отлаживать асинхронный код и какие инструменты разработчика наиболее полезны для этого?
Использовать `console.log` с метками времени, точки останова (breakpoints) в DevTools, вкладку Network для отслеживания запросов, вкладку Performance для анализа времени выполнения, а также инструменты для проверки промисов (например, в консоли браузера можно посмотреть состояние промисов).
